## Why the legacy results were invalid

The last legacy report (`legacy/reports/training_report_GA_20250927_094109.txt`)
claims accuracy = precision = recall = F1 = ROC-AUC = **1.0000**. Three
independent defects produced this:

1. **One-class test set.** The dataset is a single filter lifecycle (11,519
   rows) with a single healthy→clogged transition at row 8,943 (77.6% /
   22.4%). The legacy 80/20 temporal split cuts at row ~9,215, so the test
   set contained only "Clogged" rows. Any degenerate model scores 1.0.
2. **Label circularity.** `filter_status` is generated by the thesis's own
   7-criterion rule; `validation_score` *is* that rule's score (empirically:
   label = Clogged ⟺ score ≥ 11; the thesis text says ≥ 12 — documented
   discrepancy). The rule's score and inputs (`adaptive_cusum`,
   `cusum_threshold`, `short_ema`, `long_ema`) were used as model features,
   so the model merely re-implemented the rule. The ablation run
   (`configs/ablation_thesis_features.yaml`) reproduces this mechanistically:
   ROC-AUC 1.0000 / F1 0.9992 with those columns, vs 0.969 / 0.706 without.
3. **Wrong model promoted.** The GA run tuned and reported a RandomForest
   (gini/bootstrap/min_samples hyperparameters) under an XGBoost headline;
   the thesis specifies XGBoost + Optuna TPE.

## Enhancements beyond bug fixes (each justified)

* **Early-warning experiment** (`configs/early_warning.yaml`): y_H(t) =
  label(t+H) for H ∈ {15, 30, 60} rows; aligns with the thesis objective of
  predicting clogging *time*, and gives the anticipation behaviour a proper
  supervised framing.
* **Anticipation-aware evaluation** (#14): empirical finding — 100% of the
  XGBoost false positives form a contiguous band within ~36 minutes before
  the true onset (F1 rises 0.706 → 0.999 as the anticipation window widens
  to 600 rows), i.e. they are early warnings, not confusion. RF shows the
  mirror profile (flat F1 0.944, errors are *late* detections).
* **Sampling-interval verification** (`data.py`): the thesis's 2-minute
  storage interval belongs to the industrial SCADA data; this lab set is
  ~3.6 s/row (11,519 rows over ~11.5 h). All minute figures derived, not
  hard-coded.

## Physics & visualization pass (2026-07-03)

* **Physics formulation module** (`physics.py`,
  `docs/physics_formulation.md`): units fixed as fundamental (ΔP [kPa],
  Q [m³/h]); exact SI conversion constants; Darcy–Forchheimer formulation
  with an explicit identifiability analysis. Findings, both archived per run:
  (a) rolling Forchheimer fits are ill-conditioned at constant flow
  (median within-window Q-std ≈ 0.03 m³/h; condition numbers 10²–10³;
  B < 0); (b) even per-phase global fits are confounded by within-phase
  degradation (R² < 0). The identifiable physics: specific flow resistance
  R = ΔP/Q ∝ 1/k₁ per row, per-phase Darcy operating lines
  (R̄ rises 5.1×10⁶ → 1.1×10⁷ → 4.0×10⁷ Pa·s/m³ across the lifecycle —
  ≈ 8× permeability loss), and the fouling rate dR/dt.
* **New features**: `resistance_slope_15/30` (fouling rate). Monotone map
  refined to the principle *levels constrained, dynamics unconstrained*
  (slopes/MAD-z/differences are high during active clogging but ~0 on the
  clogged plateau — non-monotone with the state, so previously-constrained
  `dp_slope_*` / `dp_madz_30` moved to unconstrained). Headline metrics
  unchanged within CI (ROC-AUC 0.970).
* **Note recorded**: tree ensembles are invariant to monotone unit
  rescaling, so SI conversion affects interpretation/figures/tables, not the
  design matrix — stated to preempt reviewer confusion.
* **Visualization & reporting** (`docs/visualization_plan.md`): audit of
  legacy plots (superseded — they visualize leakage-contaminated runs); new
  figures: `eda_distributions`, `correlation_heatmap`, `dp_q_physics`,
  `hpo_history`, `cv_learning_curve` (time-series learning-curve form),
  `residual_analysis_h*`; publication rcParams (STIX serif, Okabe–Ito
  colorblind palette, fixed model colors, 300 dpi PNG + PDF);
  `compare_runs.py` produces the cross-run ablation figure with 95%
  block-bootstrap CI whiskers plus combined CSV/LaTeX tables;
  `reporting.export_tables` writes headline/anticipation/delay/risk tables
